# Coding Projects — archive of what was built (feature removed from Notlinear)

> **Status: removed.** This file is the record of the Coding Projects feature: what it did, how it was built, the decisions behind it, the bugs it hit, and how to bring it back. Compiled 2026-09-29 from `FEATURES.md` §3, `CHANGELOG.md`, `BUGS.md`, `docs/project-notes/{TASKS,DECISIONS}.md`, and the source itself.
>
> **Last code state:** commit `d8a3279` plus uncommitted edits in the working tree (`coding-projects.js` +228 lines, `server.py` +265 lines relative to HEAD at the time of removal). A verbatim copy of the final JS and CSS is in `docs/archive/coding-projects/` so nothing uncommitted was lost.

## 1. What it was

A Notion-style dashboard over **real local code folders**. You added a folder; Notlinear scanned it read-only, looked for `README` / `CHANGELOG` / `BUGS` / `TASKS`, and showed a "what's here / what's missing" view per project. It was strictly additive: it never touched chat threads, branches, or the chat Dexie db.

## 3. Behaviour (final state)

**Navigation.** Launched from a collapsible sidebar section ("coding projects", own `+` button) or from a blank tab's "Coding projects" tile / the tab `+` menu. Breadcrumb `coding projects / <project>`. Back and Escape step out one level at a time: popover → drawer → project page → list → chat.

**List view.** List/gallery toggle (session-sticky), rescan (clears the in-memory scan cache), "+ add folder". Order is most-recently-added first; no search or sort. Each row: icon (emoji, Mind Garden token, or folder fallback), name plus an **attention dot**, path, a **status sentence**, bug count, relative last-updated, comment count. The attention dot fired when `bugs.md` was missing, or there were open bugs and the project was stale for more than 14 days, or more than one of the four convention docs was missing. The status sentence was ~18 words ("what shipped · next: <task>"), generated by DeepSeek when configured, otherwise a heuristic, and cached per path+mtime. Bug count = unchecked `- [ ]` items in `bugs.md`. Empty state offered "add folder" (active) and "set root" (disabled, "coming later").

**Add project.** Popover with folder path, native "browse…", optional display name (defaults to last path segment), icon picker. Cancel / Add project (disabled until a path is entered). Toast "added <name>". There was **no delete-project action**.

**Project page.** Header with large icon, editable title (blur/Enter renames), path. Meta strip: `N md files · X/4 convention docs · N open bugs · updated <relTime>`. Files block: 2-column grid of every discovered markdown file, click opens the drawer, truncation notice at 200 files. Notes & comments block with composer (⌘/Ctrl+Enter), newest→oldest.

**Drawer.** Right-side slide-in with path, size (or "too large to preview"), a "reveal in Finder" button that only toasted "coming later", and a close button. Closed by button, Escape, outside click, or back.

**Comments.** One store (`nl_cp_comments_v1`), two surfaces (row popover oldest→newest, page thread newest→oldest). Author = `prefs.name` (default "You").

**Not built:** reveal in Finder, "set root" (scan a root for all projects), delete project, search/sort.

## 4. Architecture

**Files (frontend).**
- `frontend/views/coding-projects.js` (~984 lines) — the whole view; exported `initCodingProjects()`.
- `frontend/styles/coding-projects.css` (~253 lines) — all `cp-*` classes.
- `frontend/index.html` — stylesheet link; sidebar block (`#cp-side-head`, `#cp-side-list`); tab `+` tile `#bte-coding-projects`; overlay `#cp-screen` (`#cp-back`, `#cp-crumb`, `#cp-scroll`, `#cp-inner`) and drawer `#cp-drawer` (`#cp-drawer-path/size/reveal/close/body`).
- `frontend/index-design.html` — static design mock of the same overlay, sidebar block and CSS.
- `frontend/app.js` — `import { initCodingProjects }`, the `initCodingProjects()` call at startup, the `'coding-projects'` entry in the tab-strip view map (`{label:'Coding projects', icon:'ti-folder-code'}`), and the `#bte-coding-projects` click handler.

**Backend.** `backend/server.py`: the `Coding Projects scan (read-only)` section (`CP_*` constants, `_cp_*` helpers, `scan_project()`) and the two POST routes. **These stayed** — see §7.

**State (all localStorage, no Dexie — ADR-004).**
`nl_cp_projects_v1` (registry), `nl_cp_status_cache_v1` (status sentence per path+mtime), `nl_cp_comments_v1` (`{[projectId]: Comment[]}`), `nl_cp_side_collapsed_v1` (sidebar collapse).

**External calls.** `POST /__notlinear_pick_folder`, `POST /__notlinear_scan_project` (both via `loggedFetch` in `core/api-client.js`), and DeepSeek chat completions for the status sentence.

**Scan behaviour** (`scan_project`): shallow top-level listing (cap 500); convention docs found by stem (`readme`, `changelog`, `bugs`, `tasks`); recursive markdown previews (cap 200); a combined markdown + code/config context list (cap 300); per-file read cap 1 MB; skips dot-dirs, vendor dirs, lockfiles; `os.walk` pruned in place with a symlink-escape guard.

**Shared modules it consumed:** `core/registry.js`, `core/state.js`, `core/api-client.js`, `core/markdown.js` (`renderMarkdown`, `highlightCodeIn`, `esc`), `core/ui.js` (`toast`, `wireTabInsertsTab`), `core/emoji.js`, `core/mind-garden.js`.

## 5. Decisions (ADRs, verbatim numbers from `DECISIONS.md`)

- **ADR-003** — Reads the real filesystem via new additive backend endpoints (no browser File System Access API).
- **ADR-004** — State lives in localStorage, not Dexie (keeps the chat schema untouched; precedent later cited by the redesign).
- **ADR-005** — Status sentence is LLM-generated (DeepSeek), cached by file mtime, with a heuristic fallback.
- **ADR-006** — Renders as a full-screen overlay (like `.project-screen`), not an in-place main swap.
- **ADR-008** — Scans include capped recursive markdown previews.
- Related: ADR-010 (project folder scan cache, 5-minute in-memory TTL) is chat Projects, not this feature, and stays.

## 6. Bugs it produced

- **#024** — Toasts hidden behind the overlay (`.toast` z-index 300 < overlay 400); fixed by raising `.toast` to 500.
- **#025** — "create" buttons for missing files rendered as clipped 32px squares because they used the icon-only `ghost` variant; fixed by dropping `ghost`.
- **#027** — Thread-opening actions failed while an overlay was active; fixed by remounting the chat view in `renderThread`.
- **#040** — Tab key moved focus in the comment box; fixed with `wireTabInsertsTab()`.
- DeepSeek `deepseek-chat` retirement — hard-coded model string updated.
- Tab strip hidden by the full-screen overlay — overlay moved down 44px.

## 7. What deliberately stayed when the feature was removed

Discovered while grepping call sites before deleting:

1. **`/__notlinear_scan_project` and `/__notlinear_pick_folder` (backend + `scan_project`)** — chat **Projects' linked-folder context injection** calls both (`frontend/app.js`, keyword extraction → file selection → context injection). Removing them would break that. Only the "Coding Projects" wording in comments was updated.
2. **The emoji / Mind Garden picker styles (`.cp-pop`, `.cp-emoji-*`, `.mg-*`)** — `core/emoji.js` builds its popover with these class names and it is used by Notes and by chat thread/project icons. They were moved out of `coding-projects.css` into `styles/emoji-picker.css` (selectors unchanged) rather than deleted.
3. **`core/emoji.js`, `core/mind-garden.js`, `core/markdown.js`, `core/ui.js`** — shared; only comments naming Coding Projects were edited.

## 8. How to restore

1. Copy `docs/archive/coding-projects/coding-projects.js` → `frontend/views/`, `coding-projects.css` → `frontend/styles/`.
2. Re-add the stylesheet `<link>`, sidebar block, `#bte-coding-projects` tile, `#cp-screen` and `#cp-drawer` markup to `frontend/index.html` (the design mock `index-design.html` history and `git show d8a3279:frontend/index.html` have the exact markup).
3. In `frontend/app.js` re-add the import, the `initCodingProjects()` call, the tab-strip `'coding-projects'` entry, and the `#bte-coding-projects` handler.
4. The backend needs nothing — endpoints were kept.
5. Remove the duplicated picker rules from `coding-projects.css` (they live in `emoji-picker.css`).
