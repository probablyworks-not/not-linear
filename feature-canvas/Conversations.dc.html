01 · PRODUCT FRAMING

Flow Sketch

A constrained, private flow canvas inside notlinear. An embedded thinking primitive, not a whiteboard. Eleven sections below. Select any part and ask about it.

WHO IT'S FOR

PMs, founders, designers and researchers who leave notlinear, build a flow in Figma, screenshot it, and come back.

JOB TO BE DONE

“While developing an idea in notlinear, help me quickly express a sequence of screens, decisions, and outcomes without switching tools or polishing a formal design.”

The Figma screenshot workaround proves the job exists and context-switching has a cost. Before investing, learn:

02 · STRONGEST ARGUMENT AGAINST

notlinear is a thinking canvas, not a design suite.

Another full canvas risks months spent building a weaker FigJam instead of improving core branching.

!Conflicting canvas interactions and keyboard shortcuts
!A second persistence model
!A large surface for selection, zoom, undo, export, accessibility and mobile bugs
!Pressure to add drawing, comments, templates and collaboration
!Months spent on a weaker FigJam
Pressure to add drawing, comments, templates, collaboration, prototyping and hi-fi components is classic scope creep. Pursue only as an embedded thinking primitive.

04 · CORE USER FLOWS

Keyboard-first, branch-native.

Don't make users drag every item from a toolbar. Sequential creation is fastest for the dominant workflow.

Create from an ideaCORE
  1. Open a conversation or branch
  2. Add → Flow sketch
  3. Flow opens with one selected starter node
  4. Type the first screen or action
  5. Tab creates and connects the next node
  6. Changes autosave
  7. Close; a flow card stays embedded in context

Keyboard-first sequential creation beats toolbar dragging.

Branch a decisionCORE
  1. Add or convert a node to Decision
  2. Two outgoing branches appear
  3. Label them “Yes” and “No”
  4. Continue each path independently

Aligned with notlinear’s core model: branching thought, expressed spatially.

Reopen and reviseCORE
  1. Open the saved flow card
  2. Last state and viewport restored
  3. Edit labels, move nodes, add a path
  4. Autosave
  5. Embedded preview updates

For a private MVP, persistence reliability matters more than export or collaboration.

Conversation text → nodeLATER
  1. Highlight text in notlinear
  2. Choose Add to flow
  3. Pick an existing private flow
  4. Text becomes a node with a backlink to its source branch

Where notlinear beats FigJam. Build only after basic creation shows repeat use.

07 · OPEN-SOURCE EVALUATION

Which library imposes the fewest wrong assumptions?

Rete.js, LiteGraph and Drawflow lean toward visual programming and executable graphs: heavier than a user-flow sketch.

React Flow / xyflowSTRONGEST FIT
xyflow/xyflow · MIT
FOR
+ React, like notlinear
+ Custom nodes use notlinear’s design system
+ Nodes and edges serialize naturally
+ Official save/restore and undo/redo examples
+ UI stays under your control
AGAINST
− You still build node types, creation UX, copy/paste, autosave, undo state, previews, keyboard a11y

Best balance of product fit, flexibility, licensing and effort.

ExcalidrawFASTEST
excalidraw/excalidraw · MIT
FOR
+ Mature drawing interactions
+ Embeddable, React integration
+ Familiar rough-thinking look
AGAINST
− Far more than the MVP needs
− Hard to enforce semantic node types
− Data is drawing elements, not a flow model
− Feels like an app inside an app
− Persistence is still integration work

Only if users say “I need to sketch freely”, not “I need to map a flow”.

tldrawLICENSING
tldraw/tldraw · SDK license
FOR
+ Strong canvas model
+ Extensible shapes and tools
+ Mature copy/paste, undo, media
AGAINST
− Production use needs a license arrangement
− Invites broad whiteboard scope
− Excessive for a constrained flow sketcher

Evaluate only if notlinear wants a broad infinite-canvas platform.

WireflowREFERENCE ONLY
vanila-io/wireflow · OSS
FOR
+ Closest to the requested workflow
+ Draggable screens and connectors
AGAINST
− A full app is hard to integrate
− Assumptions fight notlinear’s data model
− Forking adds maintenance burden

Competitive and UX reference, not the foundation.

08 · ENGINEERING

Store the semantic model, not pixels.

PROPOSED STACK
CANVAS@xyflow/react
STATEExisting notlinear pattern; no new library without need
PERSISTENCEnotlinear backend
AUTOSAVEDebounced change sets or snapshots
IDENTIFIERSStable, client-generated
PREVIEWRead-only mini-flow, not server images
EXPORTDeferred; html-to-image after validated demand
SAVING BEHAVIOR
Save locally after every meaningful edit
Debounce server sync ~500–1,000 ms
Quiet states: Saving…, Saved, Couldn’t save
Flush on close or navigation
Keep a schema version for migrations
Optimistic concurrency, since one person may open two tabs

Reliability is the invisible core feature. Losing one diagram loses trust.

THE DIFFERENTIATOR, EVENTUALLY
