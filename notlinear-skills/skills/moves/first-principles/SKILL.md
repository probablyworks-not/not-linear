# First Principles

Strip to fundamentals, rebuild without inherited assumptions.

## How to execute

1. List the assumptions currently baked into the thing being examined — including ones so standard nobody states them ("of course it needs a database," "of course users want X").
2. For each, ask: is this actually load-bearing, or is it just how it's conventionally done?
3. Rebuild the reasoning from only what's actually necessary — physical/logical/economic constraints, not convention.
4. Compare the first-principles answer to the conventional one. If they match, say so (it's a useful confirmation). If they diverge, that divergence is the interesting part — surface it clearly.
