# Spike Plan

Design the smallest possible experiment to resolve a technical unknown before committing to a direction.

## How to execute

1. Name the specific unknown that's blocking confidence in the decision.
2. Design the cheapest, fastest experiment that would actually resolve it — not a mini version of the full build.
3. Define the success/fail signal in advance, concretely, so the spike has a clear answer rather than an ambiguous "well, it kind of worked."
4. State the time-box.
