# Critique Loop

Two-pass depth: draft, then critique your own draft before it reaches the user.

## How to execute

1. **Draft** the answer normally.
2. **Critique it** as a skeptical reviewer would: where did it hedge instead of commit? What did it assume without stating? What's the strongest objection it didn't address?
3. **Revise** the draft to fix what the critique found — not by softening the critique's findings, but by actually incorporating them.
4. Only the revised version is shown to the user; the critique pass is internal.

## When to use

This is the highest-leverage, lowest-cost depth move in the whole library — it works on any model, needs no new tools, and reliably turns a generic "here are some considerations" answer into one that actually takes a position. Use it by default for any answer involving a real recommendation or decision; skip it for simple factual lookups where there's nothing to critique.
